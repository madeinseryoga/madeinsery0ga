## 1. 🚀 Критические проблемы производительности

### 1.1 Гигантские JSON-файлы данных

| Файл | Размер | Когда грузится | Последствие |
|------|--------|---------------|-------------|
| `hsk_data.json` | **7.5 MB** | При открытии «Вся лексика» / карточки | Блокирующая загрузка, пользователь ждёт 3–10 сек |
| `pinyin_map.json` | **23.7 MB** | При пиньинь-поиске в БКРС | Критическая задержка при первом поиске |
| `bkrs_examples.json` | **6.8 MB** | При открытии БКРС (примеры) | Долгий первый поиск |
| `ru_to_zh.json` | **10.1 MB** | При русском поиске в БКРС | Дополнительная задержка |
| `single_chars.json` | **3.1 MB** | При поиске одиночных иероглифов | — |
| `core_words.json` | **2.9 MB** | — | — |

**100 бакетных файлов БКРС** (`b00.json` – `b99.json`) по 1.1–5.8 MB каждый — итого **~314 MB** в папке данных. При каждом поиске подгружается 1–6 бакетов. Первый поиск «холодный» (медленный), повторные — быстрые (кэш в памяти).

### 1.2 Монолитный HTML-файл

- Весь сайт — **один HTML-файл размером 1.3 MB**
- Содержит **13 синхронных `<script>` блоков** суммарно ~667K символов JS
  - Скрипт #6: **350 KB** — основная логика платформы
  - Скрипт #8: **226 KB** — движок БКРС + Изучение текстов
  - Скрипт #10: 45 KB
- **Ни один скрипт** не помечен `async` или `defer`
- Браузер парсит весь JS **до первого рендера** → белый экран при загрузке

### 1.3 Отсутствие оптимизаций загрузки

- ❌ Нет `<link rel="preload">` для критических ресурсов (шрифты, основной JS)
- ❌ Нет Service Worker — нет кэша, нет офлайн-режима, каждый визит грузит всё заново
- ❌ Нет WebP изображений (все файлы в PNG/JPG — устаревшие форматы)
- ❌ 8 изображений Baobao (`images/baobao_*.png`) загружаются без `loading="lazy"` всегда, даже если пользователь не смотрит на эту секцию
- ❌ Нет `Cache-Control` заголовков (можно настроить через `_headers` файл для GitHub Pages)

### 1.4 Внешние CDN-зависимости (риск в РФ)

| Ресурс | CDN | Риск |
|--------|-----|------|
| **Google Fonts** (Nunito + Noto Sans SC) | `fonts.googleapis.com` | Замедление/блокировка в РФ |
| **Font Awesome 6.4.0** | `cdnjs.cloudflare.com` | Нет иконок при сбое CDN |
| **HanziWriter** (анимации черт) | `cdn.jsdelivr.net` | При сбое → `undefined` под иероглифом |
| **html2canvas** | CDN | — |
| **jsPDF** | CDN | — |

### 1.5 Ненадёжный Google Translate API

Перевод предложений в «Изучении текстов» использует **неофициальный** эндпоинт:
```
translate.googleapis.com/translate_a/single?client=gtx
```
- Не задокументирован, не имеет SLA
- Rate-limited — при активном использовании начинает возвращать ошибки
- Риск блокировки в РФ
- При сбое кнопка «Перевод» зависает или не показывает результат

### 1.6 Дублирующийся fetch грамматики

В коде присутствуют два разных пути к одним и тем же файлам:
```js
fetch('./data/grammar_hsk1/...')  // с точкой
fetch('data/grammar_hsk1/...')    // без точки
```
Это может приводить к двойной загрузке одних и тех же JSON или к ошибкам 404 в зависимости от базового URL.

## 2. 🎨 Проблемы дизайна и UI

### 2.1 Дублирующиеся CSS-правила с конфликтами

В одном `<style>` блоке определены конфликтующие правила:

**`.bkrs-toc-bar`** — определён **дважды**:
- Первое определение (~строка 163614): `border-radius: 12px`, `border: 1px solid #e2e8f0`, `overflow-x: auto; white-space: nowrap` (горизонтальный скролл)
- Второе определение (~строка 214244): `border-radius: 16px !important`, `border: 1.5px solid #ebdcf5 !important`, `flex-wrap: wrap` (перенос строк)

Старое правило с `overflow-x: auto` создаёт горизонтальный скролл в TOC-баре вместо переноса элементов.

**`.bkrs-status-bar`** — определён **дважды** с конфликтующими свойствами.

### 2.2 Непоследовательные стили кнопок

- Кнопки в разных секциях имеют разные `border-radius`, `padding`, размеры
- `.bkrs-icon-btn`: `36×36px` с `border-radius: 10px` — выглядит квадратным, а не иконочным
- Кнопки в «Изучении текстов» до исправления были избыточно большими
- Нет единой дизайн-системы / CSS-переменных

### 2.3 Отсутствие CSS-переменных

Все цвета захардкожены напрямую в CSS (~100KB+ CSS в одном `<style>` блоке). Нет единой палитры через `--var`. Любое изменение цвета требует поиска и замены по всему файлу.

### 2.4 Раздел «Вся лексика» — незапрошенные примеры

В карточках слов появился блок «Примеры предложений» с обрезанным текстом (показывает только начало — «люб», «он гово», «n»). Этот блок не запрашивался и выглядит некорректно. Нужно либо показывать полные примеры, либо убрать блок.

### 2.5 Кнопки социальных сетей

- Кнопки «ВКонтакте», «Telegram», «YouTube», «TikTok», «Max» — ширина не выровнена (VK и Max задают левую/правую границу, между ними — непропорционально широкие кнопки)
- Текст внутри кнопок не всегда центрирован
- Иконка **Max** (стриминговый сервис, мессенджер — бывший ОК/МТС) требует официальный логотип

## 3. 🔍 БКРС · Словарь — специфические баги

### 3.1 `undefined` под анимацией черт

**Симптом:** После анимации черт иероглифа отображается текст `undefined` вместо описания или пустого места.

**Причина:** HanziWriter загружается с CDN асинхронно. В момент рендера карточки `charsDb` (база данных символов) ещё не загружена. Код обращается к несуществующему полю и получает `undefined`.

**Воспроизводится:** При поиске `你好`, `ni`, любого иероглифа — под блоком «Порядок черт (你):» отображается `undefined`.

### 3.2 `undefined` в карточках пиньинь-поиска

**Симптом:** При поиске по пиньиню (например, `ni`) под каждой char-pill кнопкой отображается `undefined`.

**Причина:** `charsDb` не загружен в момент рендера pill-кнопок, `renderColoredPinyin` возвращает `undefined` для некоторых символов.

### 3.3 Медленный первый поиск

При первом открытии БКРС-поиска происходит «холодная» загрузка нескольких бакетных файлов + `ru_to_zh.json` + `pinyin_map.json`. Суммарно может загружаться 20–30+ MB данных. На медленном интернете первый поиск занимает 5–15 секунд.

### 3.4 Пиньинь в карточке мамы — разрыв

В карточке слова 妈妈 пиньинь отображается как `mā ma` (раздельно) вместо `māma` (слитно как в БКРС). Оригинальный БКРС показывает `māma` → нужно унифицировать.

### 3.5 Ширина контейнеров БКРС

Контейнеры `.bkrs-search-container`, `.bkrs-toc-bar`, `.bkrs-result-card` установлены в 860px, но на некоторых разрешениях выходят за пределы или ломают layout.

### 3.6 Результаты поиска vs оригинальный БКРС

Количество результатов может расходиться с оригинальным bkrs.info. Пример:
- Поиск «аргон» на bkrs.info → несколько результатов
- На нашей платформе → может показывать меньше или больше

Необходима периодическая верификация (30 случайных русских слов, 30 иероглифов, 10 пиньинь, 10 предложений) по сравнению с оригиналом.

### 3.7 Раздел «По иероглифам» в «Вся лексика»

Блок разбора по иероглифам присутствует, но его нужно убрать (был запрос на удаление).

### 3.8 Кнопка «Статья в БКРС» в «Вся лексика»

Кнопка «Статья в словаре БКРС» не работает. Должна открывать страницу на bkrs.info. Также её позиция была запрошена — переместить рядом с кнопкой прослушивания.

## 4. 📖 Раздел «Изучение текстов»

### 4.1 Плашка раздела не скруглена

Плашка «Изучение текстов» — прямоугольная, не скруглённая как у других секций. `border-radius` не применён.

### 4.2 Деление предложений работает нестабильно

При первом открытии текста сегментация иногда даёт неправильное деление (показывает иероглифы слипшимися или делит не по границам слов). При повторной загрузке результат правильный. Поведение непредсказуемо.

**Ожидание:** Деление должно всегда соответствовать паттерну из БКРС (как при корректном отображении).

### 4.3 Перевод работает медленно

Кнопка «Перевод» у каждого предложения вызывает неофициальный Google Translate API. При rate-limit или плохом интернете ответ не приходит вовсе (кнопка зависает).

### 4.4 Лингвистический анализ очень медленный / не загружается

Вкладка «Лингвистический анализ» в текстах долго загружается или не загружается вовсе. Вероятно, зависит от тех же тяжёлых JSON + дополнительных вычислений.

### 4.5 Кнопки «Копировать» у сегментов

Нужна кнопка «Копировать» у каждого текстового блока/предложения, чтобы пользователь мог скопировать текст в сторонний переводчик. Из-за pinyin-разметки простой Ctrl+C не копирует чистый китайский текст.

## 5. 📚 Раздел «Вся лексика»

### 5.1 Незапрошенный блок примеров

В карточках лексики появился блок «Примеры предложений» с обрезанными переводами. Этот блок не заказывался. Переводы показываются частично (обрезка: «люб», «он гово», «n»). Убрать или показывать полностью.

`hsk_data.json` = 7.5 MB загружается при каждом открытии раздела «Вся лексика» или при первом обращении к карточкам. Это главная причина медленного отклика секции.

## 6. 📱 Мобильная версия

### 6.1 Маскот Baobao занимает место

На мобильных устройствах маскот (Baobao) отображается и занимает значительную часть экрана. Его нужно полностью скрывать на мобилке (`display: none` при `max-width: 768px`).

### 6.2 Нижний dock перекрывает контент

Навигация (нижняя панель dock) на мобилке может перекрывать последние элементы контента на странице. Нужно добавить `padding-bottom` к основному контейнеру равный высоте dock-панели.

### 6.3 Переключение дипломов медленное

В разделе «Об авторе» переключение между сканами дипломов происходит медленно на мобильных устройствах. Изображения не предзагружаются. Нужен `preload` следующего/предыдущего скана при наведении/тапе.

### 6.4 Кнопки слишком большие на мобилке

Некоторые кнопки (в «Изучении текстов» и БКРС) сохраняют десктопный размер на мобилке, занимая слишком много пространства.

## 7. 🏗️ Архитектура и технический долг

### 7.1 Три файла нужно синхронизировать вручную

`current_decrypted.html` → `app.html` → `index.html` — все три должны быть идентичны. Нет автоматизации, риск рассинхронизации при каждом изменении.

### 7.2 Нет системы сборки

Весь проект — ручное редактирование HTML. Нет:
- Минификации JS/CSS
- Tree-shaking неиспользуемого кода
- Автоматического разбиения на чанки
- Hot reload при разработке

### 7.3 Глобальные переменные вместо модулей

Более 20 переменных вида `window.__*` используются для связи между разными частями кода (вместо нормального импорта/экспорта ES-модулей). Любое изменение в одной части может сломать другую.

### 7.4 Весь CSS в одном блоке ~100KB+

Один огромный `<style>` блок с правилами для всех секций. Нет разделения по компонентам, нет CSS-переменных. Крайне сложно поддерживать.

### 7.5 Нет обработки ошибок при загрузке данных

Если JSON-файлы не загрузились (timeout, 404, ошибка сети) — пользователь видит пустой экран или `undefined` без информативного сообщения об ошибке.
